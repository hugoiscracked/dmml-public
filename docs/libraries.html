Library Reference

Every library the exercises import, in one place. For each one: what it is, how it thinks, where its real documentation lives, and the handful of functions you will actually call this semester. Nothing here replaces the official docs — the point is to make them approachable, so a new import stops feeling like a black box someone dropped into the notebook.

The stack, bottom to top

Almost every library in this course sits on the one below it. Knowing which layer you are on tells you where to look when something breaks.

NumPyTyped arrays and fast numeric operations. Everything above stores its numbers here. pandasNumPy arrays with labels: columns, an index, and missing values. The shape of tabular data. MatplotlibThe drawing engine. Slow to write, capable of anything. seabornStatistical shortcuts over Matplotlib that speak DataFrame. scikit-learnOne uniform interface over classical models, preprocessing, and evaluation. statsmodelsThe statistician's parallel branch: inference, diagnostics, time series. SHAPSits on top of a fitted model and attributes its predictions to features. PyTorchTensors with automatic differentiation. Replaces sklearn's .fit() with a loop you write. torchvisionImage datasets, transforms, and pretrained vision weights for PyTorch.
datasets · transformersHugging Face: dataset loading and pretrained language models, also on PyTorch.

The pattern worth internalising: a library is usually one core object plus a contract for using it. NumPy has the array. pandas has the DataFrame. scikit-learn has the estimator with fit/predict. PyTorch has the tensor and the module. Learn the object and the contract, and the hundreds of functions become searchable details rather than things to memorise.
